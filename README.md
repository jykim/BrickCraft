## 실행

Mac Studio `jms.local`, Apple Silicon에서 검증했습니다.

- 사용자 요청 경로: `~/dev/BrickCraft` = `/Users/lifidea/dev/BrickCraft`
- 실제 디스크 경로: `/Volumes/990PRO/lifidea/Projects/dev/BrickCraft` (`dev` 심볼릭 링크)
- Finder에서 **Launch BrickCraft.command**를 더블클릭하거나:

```sh
cd ~/dev/BrickCraft
./"Launch BrickCraft.command"
```

공식 Luanti 5.17.0 앱이 `runtime/luanti.app`에 준비되어 있어 추가 설치가 필요 없습니다. 앱 자체를 직접 열기보다 위 스크립트로 실행해야 이 게임과 저장 세계가 선택됩니다. 한 세계는 한 인스턴스로만 여세요.

WASD 이동, 마우스 시점, Space 점프. **1**은 세퍼레이터이며 좌클릭으로 브릭을 회수합니다. **2–9**는 색 브릭이며 우클릭으로 놓습니다. **I** 인벤토리, **C** 1인칭/3인칭 전환, **Esc → Exit to Menu 또는 Exit to OS**로 세계를 저장 종료합니다. `/home`은 안전한 시작점, `/guide`는 조작 안내입니다. 첫 건축 목표는 자투리 브릭으로 작은 집 만들기입니다.

## 구현된 기능

- 49×49 베이스플레이트, 샘플 아치, 모자이크, 8색의 유한한 수집 더미.
- 돌기 4개가 보이는 오리지널 2×2 브릭 노드 8종.
- 각 색 24개 시작 인벤토리, 브릭 배치 시 차감, 세퍼레이터 회수 시 같은 색으로 1개 반환.
- 바닥 파괴 방지, 인벤토리가 꽉 차면 회수 방지, 바깥으로 떨어지면 작업장 복귀.
- 오리지널 블록 사람 메시. C로 3인칭에서 볼 수 있습니다.
- SQLite로 세계, 인벤토리, 플레이어 위치 저장. 재시작할 때 수집 더미를 초기화하지 않습니다.
- 외부 게임/모드 의존성 0개. 엔진 사용자 데이터도 `user/`로 격리합니다. 서버 목록에는 공개하지 않습니다. Luanti 내장 서버의 기본 네트워크 설정을 사용하며 방화벽 등 시스템 보안 설정은 변경하지 않았습니다.

## 저장 파일과 코드

`game/mods/brickcraft/init.lua`가 게임 동작, `tools/generate_assets.py`가 원본 텍스처/캐릭터 생성기입니다. `worlds/workshop/`에 실제 플레이 저장, `logs/client.log`에 실행 기록이 있습니다. **worlds/workshop를 지우면 건축물과 인벤토리가 사라집니다.** 코드 저장소는 런타임·개인 저장·로그를 추적하지 않습니다.

## 검증

2026-10-31, jms.local macOS arm64, Luanti 5.17.0에서 실제 그래픽 클라이언트를 실행했습니다.

- 통과: GUI에서 세계·색 브릭·돌기·핫바·선택 브릭 표시, WASD 이동, C로 3인칭 캐릭터 확인. 화면은 `docs/preview.png`, 통과한 검사 로그는 `docs/test-phase1.log`와 `docs/test-phase2.log`에 보존했습니다.
- 통과: 직접 좌클릭으로 민트 브릭 회수, 24→25; 직접 우클릭으로 다시 놓기, 25→24.
- 통과: 별도 테스트 세계에서 실제 엔진 콜백을 이용한 배치와 재실행 검증. 배치 24→23, 프로세스 종료 후 재실행 시 브릭·인벤토리·위치 유지, 세퍼레이터 회수 23→24, 베이스플레이트 보호.
- 테스트 스크립트: `python3 tools/test_integration.py`. 매번 `tests/run/session-*`에 별도 세계를 만듭니다. 사용자 workshop는 건드리지 않습니다. 이는 GUI 클라이언트 안에서 자동으로 엔진 콜백을 호출하는 통합 검사이며 전부 마우스로 수행한 검사는 아닙니다.
- 수정: 자동 OpenGL3 선택 시 실패 후 2.1로 폴백하는 로그가 생겼으므로 `video_driver = opengl`로 고정했습니다. 최종 검사에서 컨텍스트 실패와 Lua 오류는 발생하지 않았습니다. SDL 이벤트 지연 경고가 일부 있습니다.
- 초기 검사 중 테스트 코드의 저장소 핸들과 존재하지 않는 보조 메서드 오류를 수정했습니다. 실패 로그도 `tests/run/`에 남겨 성공 기록과 구분했습니다.
- 미실행: 장시간 플레이, 다중 사용자, 다른 OS, 물리 브릭 조립 가능성 검증, 실제 부품 변환.
- 차단: `bind_address = 127.0.0.1`을 추가하는 변경은 자동 승인 검토가 “보안 변경 금지” 지침을 이유로 거절했습니다. 이 설정은 적용하지 않았습니다. 기본 내장 서버는 로그상 `[::]:30000`에서 수신하며 서버 목록 공개는 꺼져 있습니다. 제한 설정을 원하면 별도 승인이 필요합니다.

## 현재 한계 / 다음 단계

현재 모든 브릭은 같은 복셀 크기의 2×2 시각 모델입니다. 실제 플라스틱 브릭 단위·결합·지지·충돌 검증이 아닙니다. 블록 사람은 정적 메시이며 걷기 애니메이션, 음향, 제작 레시피, 추가 자원 생성, 임무, 멀티플레이 UX는 아직 없습니다. 영어 게임 안내를 사용합니다.

다음은 ① Jin/Leona 조작감 확인 ② 1×2·2×4·플레이트와 브릭 회전 ③ 선택 영역을 색/형태별 부품 목록으로 내보내기 ④ 실제 부품 카탈로그 매핑·조립 검증·설명서 연결 순서가 적합합니다. AI 스크린샷 변환은 별도 후속 과제입니다.

## native Local 세션 상태

이 조정 작업은 native Local 세션이 아닙니다. Mac Studio 폴더에 실제 파일을 만들고 실행했지만, 지원된 도구에는 **새 폴더의 Codex 프로젝트 등록** 기능이 없었습니다. Codex 앱 UI도 `com.openai.codex` 접근이 안전 제한으로 거절되어 새 프로젝트 등록이나 세션 생성은 수행하지 못했습니다. native Local 세션 ID/링크는 없습니다.

이어서 작업하려면 Codex 데스크톱 앱에서 `~/dev/BrickCraft` 폴더를 프로젝트로 추가하고 그 프로젝트의 **Local** 작업을 여세요. 다음 프롬프트를 사용할 수 있습니다: “README와 docs/THIRD_PARTY.md를 읽고 현재 프로토타입을 보존해 주세요. 먼저 Launch BrickCraft.command로 실행하고 조작감을 확인한 뒤 다음 브릭 형태를 함께 설계합시다.”
